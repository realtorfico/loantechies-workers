# loantechies-news

A Cloudflare **cron Worker** that builds the LoanTechies daily loan-news feed. Once a day it fetches
a curated set of mortgage/housing RSS feeds, keeps the loan-relevant items from the last ~48h,
dedupes + sorts them, and writes the result to **KV** under the key `latest`.

Each kept article also gets a short **original** "Loan Techies take" (What happened / What it means
for you), generated by **Cloudflare Workers AI** (a free open model — no API key, no separate
billing; needs an `AI` binding on the Worker). Summaries are cached per-URL in KV. We never
republish the source text — the card links out to the original.

The public site reads the `latest` key through its own Worker (`GET /api/articles` in
`Websites/loantechies/worker.js`) and renders the `/news` page + the homepage "Latest Loan News"
widget — each card an accordion that expands to the summary + a link to the source.

- `src/index.js` — single self-contained module. `scheduled()` runs the aggregation; `fetch()` is a
  manual trigger / inspector. The curated `FEEDS` list + `KEYWORDS` gate sit at the top — **edit
  those to tune the site's news**, then redeploy.
- `wrangler.toml` — daily cron, the `NEWS` KV binding, and the optional `TRIGGER_TOKEN`. NOTE: when
  you deploy by pasting into the dashboard (not `wrangler deploy`), this file is ignored — set the
  cron trigger and KV binding in the dashboard UI instead (see below).

## One-time setup (shared KV namespace)

The cron Worker (writer) and the site Worker (reader) must point at the **same** KV namespace.

**Dashboard (works on ARM64 where wrangler can't run locally):**
1. Cloudflare dashboard → **Storage & Databases → KV → Create namespace**, name it
   `loantechies-news`. Copy the namespace **ID**.
2. Paste that ID into **two** places:
   - `wrangler.toml` here → `[[kv_namespaces]]` → `id`.
   - `Websites/loantechies/wrangler.jsonc` → `kv_namespaces[0].id`.
3. Deploy both (the site redeploys on its normal git push; deploy this Worker as below).

**Or via CLI** (if wrangler runs on your machine):
```bash
cd Workers/loantechies-news
npx wrangler kv namespace create NEWS   # prints the id — paste it into both configs
```

## Deploy

```bash
cd Workers/loantechies-news
npx wrangler login        # one-time
npx wrangler deploy       # publishes the Worker + registers the daily cron
```

After deploy:
- **Populate it now (don't wait for 6am):** open
  `https://loantechies-news.<your-subdomain>.workers.dev/?run=1` (append `&token=…` if you set
  `TRIGGER_TOKEN`). It runs the aggregation and returns the JSON it just stored.
- **Inspect current data:** open the Worker URL with no query — it dumps the KV payload.
- **Confirm the schedule:** dashboard → the Worker → **Triggers** shows `10 13 * * *`.
- **Tail live runs:** `npx wrangler tail`.

## Tuning

- **Sources / keywords:** edit `src/feeds.js` (`FEEDS` and `KEYWORDS`) and redeploy.
- **Cadence:** edit `crons` in `wrangler.toml` (UTC). `10 13 * * *` ≈ 6:10am PT.
- **How many / how fresh:** `MAX_ITEMS`, `MAX_AGE_MS`, `SUMMARY_LEN` constants at the top of
  `src/index.js`.
- **Protect the manual trigger:** `npx wrangler secret put TRIGGER_TOKEN`.
